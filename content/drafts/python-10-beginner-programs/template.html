Most beginner Python lists show you the code and stop there. You copy it, run it, and something different appears on your screen, or an error you've never seen, and there's nothing to compare against. So for this list I ran every program on Python 3.12 and pasted the exact output underneath it. Then I broke five programs on purpose, because the error messages are where beginners actually get stuck.

These are small, practical programs built around things you'd calculate anyway: splitting a restaurant bill with GST, working out a loan EMI, comparing FD interest. If you're following a longer plan like our 30-day Python roadmap, these fit around weeks one and two.

Before You Start

Install Python from python.org (on Windows, tick "Add python.exe to PATH" in the installer). Save each program in a file such as main.py and run it from a terminal with:

python main.py

Each output block below is exactly what the terminal printed. Where a program asks for input, I've noted what I typed.

3. Loan EMI Calculator

This uses the standard reducing-balance EMI formula that banks use: EMI = P × r × (1+r)n ÷ ((1+r)n − 1), where r is the monthly interest rate and n is the number of months.

{{P3}} {{OUT P3}}

For a ₹5 lakh loan at 10.5% over 5 years, the EMI comes to ₹10,747, which matches what bank EMI calculators show for the same inputs. The comma in :,.0f adds thousand separators. Python groups digits in threes (644,817), not the Indian lakh style (6,44,817); formatting in lakhs needs a little extra code.

4. Simple vs Compound Interest on an FD

{{P4}} {{OUT P4}}

Most Indian bank FDs compound quarterly, which is why the formula divides the rate by 400 (4 quarters × 100 for the percentage) and multiplies the years by 4. Over three years, compounding earns about ₹2,144 more on ₹1 lakh than simple interest would.

The Five Errors You'll See First

I broke five small programs on purpose so you can see the real messages. The file path in each traceback is shortened to main.py; everything else is exactly as Python printed it. The line to read first is always the last one; it names the error type.

TypeError: adding text and a number

{{E_type}}

I typed 29 at the prompt:

{{OUT E_type}}

input() returned the text "29", and Python won't add text to a number. Fix: age = int(input("Age: ")). The ~~~~^~~~ markers under the line point at exactly which operation failed.

IndentationError: the missing spaces

{{E_indent}} {{OUT E_indent}}

Python uses indentation to know what belongs inside a loop or if. The line after a colon must be indented (four spaces is the convention). This error appears before the program runs at all, which is why there's no "Traceback" line.

NameError: a typo in a variable name

{{E_name}} {{OUT E_name}}

Recent Python versions add "Did you mean" suggestions, which catch most typos like this one. Older tutorials and videos won't show this hint, so it's a good reason to install a current version.

ZeroDivisionError

{{E_zero}} {{OUT E_zero}}

Any division where the bottom number could be zero needs a check first, for example if people > 0:. In the bill-splitting program, this happens as soon as someone enters 0 people.

FileNotFoundError

{{E_file}} {{OUT E_file}}

The file is called expenses.csv (from program 10) but the code asks for expense.csv. The other common cause is running the program from a different folder than the file is in, because Python looks relative to wherever the terminal currently is.
